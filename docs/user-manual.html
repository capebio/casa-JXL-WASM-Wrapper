Critical Behavioral Contracts

  • decode_budget_exceeded → frameStream.end() graceful partial frame, then done() rejects with BudgetExceeded. This is finishWithError(), not fail() — the stream ends, not fails.
  • scheduler.onMessage(sessionId, handler) returns void — no unsubscribe function.
  • scheduler.send() is fire-and-forget — does not throw on dead sessions.
  • decoder.push() (WASM) is synchronous — cannot yield mid-push. Hard cancel is soft between chunks.
  • postMessage(msg, [pixels]) detaches the ArrayBuffer — cannot be recycled into a pool.
  • Workers are stateless between sessions — caching WASM decoder state across recycle() would break isolation.
  • SharedArrayBuffer requires COOP/COEP headers: Cross-Origin-Opener-Policy: same-origin + Cross-Origin-Embedder-Policy: require-corp.

CASAVA — Casabio's Video Apparatus

CASAVA is Casabio's video container format. On-disk magic: CASV, file extension .casv. Implemented in crates/raw-pipeline/src/casa_video.rs (Cargo feature: jxl-codec).

Architecture: JXL VarDCT intra I-frames + REPLACE-skip P-frames. Changed regions are re-encoded as fresh JXL stills; unchanged regions are skipped entirely. The encoder never decodes its own output — change detection runs on source frames, so errors never accumulate.

Why not additive residuals?
Additive lossy residual coding was tested and rejected. JXL's perceptual model misjudges residual planes — errors accumulate rather than cancel. See docs/superpowers/specs/2026-07-01-jxl-video-codec-design.md §8. REPLACE semantics with source-frame detection is the design that works.

The lossy streaming tier. GOP = 24 frames. Change-detection threshold auto-derived from distance via default_thresh_for_distance. Batch encode is frame-parallel (into_par_iter; 4.3–5.6× measured on Ghana dashcam corpus).

Rate Control (landed 2026-07-03)

Target a byte rate instead of a fixed distance. Streaming encoders only; batch stays fixed-distance and the None default is bit-identical to before.

Implementation: closed-loop VBV feedback — zero probe encodes. The finished GOP's measured bytes steer the next GOP's distance. Converges in a few GOPs.

// Distance update law (applied at each GOP boundary):
// d_next = d_prev * sqrt(actual_bytes / target_bytes)
// Plus a leaky-bucket VBV term, clamped to [min_distance, max_distance]
// StreamCtx::set_distance rebuilds the reused encoder + re-derives auto threshold

CasaVideoOptions::streaming_bitrate(start_distance, target_bytes_per_sec)
// or explicit:
let opts = CasaVideoOptions { rate_control: Some(RateControl { .. }), .. };

Rate Metadata Format

  • Header files (jolt_encode, encode_casv_video): CasvHeader.flags — bit 0 = lossy, bits 8..15 = round(distance×10), bits 16..19 = effort. Accessors: CasvHeader::{is_lossy, lossy_distance, rate_effort}. Lossless files have flags == 0; decoders ignore it entirely — fully backwards-compatible.
  • Footer/streamed files (jolt_encode_stream_to): 8-byte CASR rate box [u32 'CASR'][u32 flags] between the index and footer. Legacy readers never look there. parse_casv_rate_box returns None for legacy files.

Rust API

use raw_pipeline::casa_video::{
    jolt_encode, jolt_encode_stream_to,
    JoltPreset, CasaVideoOptions, parse_casv_rate_box,
};

// Batch (all frames resident) → header-format .casv
let casv = jolt_encode(&frames, w, h, 24, 1, JoltPreset::Balanced)?;

// Streaming to a sink (prev+current frame resident) → footer format + CASR rate box
jolt_encode_stream_to(&mut source, JoltPreset::Realtime, &mut file)?;

// Full knobs when presets don't fit:
let opts = CasaVideoOptions::jolt(JoltPreset::Quality);  // then modify fields

// Byte-rate target (streaming only; batch stays fixed-distance):
let opts = CasaVideoOptions::streaming_bitrate(1.0, 500_000); // 500 KB/s

FableBraid — SIMD-Rate Lossless Codec

CASAVA's lossless tier. Bypasses libjxl entirely — a new Rust module with 8-way braided rANS entropy + mod-256 row predictors. Decode is SIMD/ILP-bound rather than dependency-bound (unlike JXL's serial per-pixel Huffman chain, which is 93–100% of lossless decode cost).

Why a new format?

Profiling (casa_prof, compile-gated in libjxl-012) showed no local rewrite of JXL can break the serial Huffman dependency chain. FableBraid replaces the format. Each of the 8 rANS lanes is independent — entropy decode overlaps across lanes, and prediction is one vpaddb pass. The result is 7–16× faster decode than fjxl-e1 on BBB keyframes.

Wire format

// Image container
"FBR1" | u32 w | u32 h | u8 nplanes | u8 rct
// rct: 0=none, 1=subtract-green (R-=G, B-=G mod 256)
// Per plane: u32 len | plane_blob

// Plane blob:
u8  predictor      // 0=Zero  1=Top  2=External(prev-frame plane)
u8  reserved       // 0
h × u8 row_modes   // 0=COPY(residual all-zero)  1=RANS  2=RAW
u32 n_syms
// [if n_syms > 0]
  256 × u16 freqs  // normalized to 4096
  8   × u32 initial_rans_states
  u32 rans_len | rans_bytes
u32 raw_len | raw_residual_bytes

Performance vs JXL (BBB 854×480 keyframe, i7-10850H, single-thread)

  • Decode: 7–16× faster than fjxl-e1 (effort-1 lossless JXL)
  • Size: −29..+6% vs JXL-e3 bytes — all gates met
  • All outputs byte-exact; asserted on every decoded frame in A/B bench

Full per-frame table: docs/FableBraid-spec.md §Results. Encoder is two-pass (speed secondary); decode speed is the deliverable.

Perceptual Metrics

PerSee (Perceptual Seeing) is our fast perceptual metric — a Rust SIMD approximation of Butteraugli, compiled from one source two ways: WASM v128 for the browser byte-cutoff worker, and AVX2+FMA (+ optional AVX-512) for native Tauri/server ingest. It replaces the earlier JS web/jxl-butteraugli.js scorer. Designed for throughput at scale — millions of progressive-pass comparisons per session.

PerSee vs libjxl Butteraugli
PerSee is a fast heuristic approximation, not libjxl ground truth. libjxl's ButteraugliInterfaceInPlace (exported from bridge.cpp as jxl_wasm_butteraugli_compare) is the gold standard — a full Laplacian pyramid + XYB + masking model. It is a fidelity/calibration tool only; at 14–15 seconds per 20.5 MP image it is entirely off the table for real-time or per-frame use. PerSee is what ships.

JS Fallback (browser)

web/jxl-butteraugli.js — the original JS Butteraugli-inspired scorer. Same XYB + box-blur + 3-scale p-norm algorithm; not bit-exact with libjxl. Still used in the browser progressive convergence loop (measureConvergenceProfile in backends.ts:277).

_jxl_wasm_ssim_compare(ptr1, ptr2, w, h) is exported from the split dec/enc WASM builds. Engine choice (JS vs WASM, copy vs zero-copy view buffer) is pending the 4-way flipflop in .flipflop/tests/ssim-buffer-engine.mjs.

Perceptual Constancy Mode

A separate, runtime-only colour adjustment engine in crates/raw-pipeline/src/pipeline.rs (apply_tone_math hot path). Not the same as the Butteraugli-replacement kernel above.

When PipelineParams.perceptual_constancy = true: illumination-invariant exposure/saturation/white-balance using a log-space foundation grounded in Bujack et al. 2022/2025 (non-Riemannian colour geometry). Targets AR plant recognition and photogrammetry workflows — specimens read consistently under varying light. Also improves early progressive-frame usability for ML/AR pipelines (consistent features even on DC-only passes).

Status: stub + log-space foundation in place. Full B-matrix + Molchanov tensor integration planned as LUT/SIMD accelerated path. Runtime-only — never baked into ingest.

16-bit Metric Variants (2026-07-05)

The three metrics above run at 8-bit (255² PSNR peak, u8 XYB LUT) and drive the runtime progressive-convergence loop. The codec-comparison benchmark needs distortion resolved at full bit depth — an 8-bit metric quantises away the >8-bit signal, which would make a 16-bit RD curve a mere mirror of the 8-bit one. Three 16-bit variants:

16-bit / HDR Codec Comparison (2026-07-05)

A real 16-bit rate-distortion path in the codec-paper suite (CodecPaperFullTest.mjs), replacing the former static "16-bit/HDR" capability-matrix row. Source is the project's own RAW-derived high-bit-depth content — the honest >8-bit source.

StageWhat
Source RAW → display-referred RGBA16 render. New flag OUT_FULL_DISP16 (=32) on process_{orf,cr2,dng}_with_flags → take_rgb16_disp(), then downscale_rgb16_pub + rgb16_to_rgba16 to a 1920 long-edge. Reuses the existing pipeline::process_16bit render at full-range [0,65535]; disp16>>8 matches the shipped 8-bit render to 0.0000%.
Codecs JXL (our facade, format:'rgba16'), AVIF 10/12-bit (sharp), PNG-16 (lossless anchor, bit-exact). JPEG/WebP are 8-bit-only and excluded; @jsquash/jxl is 8-bit-only, so there is no jxl_orig 16-bit reference.
Metrics psnr16 + ssim16 (JS) always; butteraugli16 (WASM bridge) when present. See Perceptual Metrics → 16-bit Metric Variants.
Figures rd-{psnr,ssim,butteraugli}-16bit.svg + lossless-16bit-size.svg (PNG-16 floor) + a "16-bit / HDR Rate-Distortion" gallery section.
Additive-metric design

The 16-bit Butteraugli bridge needs an Emscripten rebuild — the one high-risk step. It is additive: butteraugliDistance16 returns null when the symbol is absent → the driver omits butteraugli16 from the row → the figure and its gallery entry are omitted, while PSNR-16/SSIM-16 still render. The deliverable is never blocked on the rebuild.
